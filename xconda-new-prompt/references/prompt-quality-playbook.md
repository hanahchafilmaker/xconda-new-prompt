# 프롬프트 품질 플레이북 — 더 잘 쓰는 6개 지렛대 + 고치는 순서

> 프롬프트 품질은 문장을 화려하게 쓰는 게 아니라 아래 몇 개 "지렛대"로 결정된다.
> 효과 큰 순서로 정리했다. troubleshooting.md(증상→처방)와 짝으로 쓴다.

## 6개 지렛대 (효과 큰 순서)

### 1. 레퍼런스 역할을 먼저 못 박는다 (제일 큼)
각 레퍼런스가 무엇을 담당하고 무엇을 안 가져오는지 명시.
- ⭕ `@Image1 — 이 인물의 얼굴·옷에만 쓰고, 주변 세트나 빛은 가져오지 않는다.`
- 분류 트리거 단어(background/lighting/배경/조명)를 인물 설명에 쓰지 않는다 → `reference-numbering.md`(구 §7-B)

### 2. "의도"가 아니라 "보이는 것"을 쓴다
모델은 화면에 보이는 것만 그린다. 감정·분위기는 관찰 가능한 사건으로 번역한다.
- ❌ 긴장된 분위기
- ⭕ 손가락이 책상을 두 번 두드리고, 눈이 문 쪽으로 빠르게 움직인다
- 사건을 시간 순서대로. 반응·상태 변화까지. (08번 타임라인 → `beat-timeline.md`)

### 3. 추상어 대신 구체값
구체적일수록 재현이 안정된다.
- "넓은 방" → "가로 12m·세로 8m, 천장 3m" (공간 좁게 나옴 방지 → `framing-and-scale.md`)
- "다양한 얼굴" → "각진 턱 40대, 마른 20대, 광대 넓은 중년" (얼굴 뭉개짐 방지 → `background-cast.md`)
- 화각은 도(°) 9단계 앵커에서만(대화 기본 47°) → `creative-reference-tables.md`

### 4. 한 정보는 한 블록에서만 (SKILL.md §5)
같은 걸 두 군데 쓰면 강조가 아니라 충돌 → 모델이 하나를 버린다.
조명=03 · 카메라=04 · 얼굴=02+06 · 소품·의상=05 · 액션·타이밍=08.

### 5. "하지 마라" 대신 "이 상태를 유지하라" (SKILL.md §6 포지티브 락)
- ❌ 카메라 흔들리지 마
- ⭕ 카메라는 처음 선 자리에 그대로 머물며 거리와 화각을 유지한다
- 잔류 네거티브는 화면 아티팩트 최대 3줄만.

### 6. 두 단계로 간다 — 이미지 먼저, 그 다음 영상
텍스트→영상(t2v)보다 **키프레임 이미지 생성 → 그 이미지로 영상(i2v)** 이 훨씬 통제된다.
좋은 레퍼런스 스틸 1장이 프롬프트 열 줄보다 강하다.
- 얼굴 락 레퍼런스 스틸 요령: 정면·눈은 카메라·머리 뒤로(얼굴 안 가림)·균일한 정면광·그림자 없음·무배경(회색)·눈높이 50mm·중립 표정. 자세한 작성법 → `references/reference-image-prompts.md`.

## 가장 중요한 습관 — 고칠 땐 한 번에 하나만
안 나올 때 프롬프트를 통째로 다시 쓰지 않는다.
1. 생성한다
2. `troubleshooting.md`로 원인 **1개** 진단
3. 그 지렛대 **하나만** 바꾼다
4. 재생성한다
여러 개를 동시에 바꾸면 무엇이 효과였는지 영영 알 수 없다.

## 안 나올 때 무엇부터 바꾸나 (우선순위)
| 문제 | 먼저 손대는 지렛대 |
|---|---|
| 얼굴이 흔들림/뭉개짐 | ① 레퍼런스 역할 + ⑥ 좋은 스틸(정면·균일광) |
| 공간이 좁게 나옴 | ③ 미터 앵커 + 4단 깊이 (`framing-and-scale.md`) |
| 배경 인물이 마네킹 | ③ 얼굴 다양성 5축 + 4요소 (`background-cast.md`) |
| 지시가 무시됨 | ④ 한 정보 한 블록(중복 제거) + @태그 인라인 호출 |
| 원치 않는 것이 계속 나옴 | ⑤ 포지티브 락으로 뒤집기 |
| 전반적으로 통제가 안 됨 | ⑥ t2v 대신 이미지→i2v 두 단계로 |
