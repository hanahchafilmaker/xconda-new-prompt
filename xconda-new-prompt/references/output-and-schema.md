## 13. 산출물 구조 — 엔진 + 씬 데이터 (v8 표준)

> **v8 대전제**: 편집기를 씬마다 새로 만들지 않는다. **엔진 HTML(기능, 고정) 한 번 +
> 씬 JSON(내용, 자주 수정)** 으로 나눈다. v6.4의 "통합 편집기 한 파일"(구 §13-E)은
> **폐기**한다 — 데이터를 자주 고칠 때 거대한 HTML을 부분 수정하다 함수가 사라지는 사고가
> 반복됐기 때문이다.

### 세 산출물 (엔진 · 씬 데이터 · 임베드본)

| | 엔진 `xconda_engine.html` | 씬 데이터 `scene_[id].json` | 임베드본 `xconda_[id].html` |
|---|---|---|---|
| 담는 것 | 렌더·검수·평면도·복사 기능 | 공간·레퍼런스·파트별 데이터 | 엔진 + 씬을 하나로 (자동 로드) |
| 수정 빈도 | 거의 안 함 (고정) | 자주 | 씬 고칠 때마다 재생성 |
| 여는 법 | 씬 JSON을 드롭 | (엔진에 드롭/임베드) | **열면 바로 뜸 (드롭 불필요)** |

- **엔진**은 데이터 없는 껍데기로, 씬 JSON을 드롭하면 채워진다. 데이터를 고칠 때 엔진 코드를
  안 건드리므로 부분수정 사고가 원천 차단된다.
- **임베드본**은 씬 데이터를 엔진 스크립트에 심어(`EMBEDDED_SCENE` 상수 + 자동 로드), **파일만
  열면 드롭 없이 바로** 파트 탭·평면도·프롬프트가 뜬다. 사용자에게 건네는 "완성본"이다.
- **씬 JSON을 만들면 임베드본에 심어서 낸다**(§13-E). 사용자에게는 씬 데이터 JSON을 따로
  주지 않는다 — **임베드본 `.html` 안에 들어 있다**. 데이터를 고칠 땐 Claude가 (자기 작업
  공간의) 씬 JSON을 고쳐 임베드본을 재생성한다.

### 출력 규칙 — 사용자에게 주는 것은 임베드본 + 프리셋뿐

- 프롬프트를 완성해도 대화창에 코드블록으로 뿌리지 않는다.
- **사용자에게 주는 산출물은 두 가지뿐**:
  1. **임베드본 `xconda_[sceneId].html`** — 씬 데이터가 안에 임베드된 완성본. 열면 바로 뜸.
  2. **파트별 보드 프리셋 `preset_[sceneId]_[part].json`** — 블로킹 보드에 넣는 `state.items`
     형식(§13-B). 프롬프트가 완성된 파트만 뽑는다.
- **씬 데이터 JSON(`scene_[id].json`)은 사용자에게 주지 않는다** — 임베드본 html 안에 있다.
  (Claude 작업 공간에는 원본으로 두고 수정·재임베드에 쓴다.)
- **보드는 씬 JSON(scene-v1)과 프리셋(state.items) 둘 다 직접 읽는다.** 씬 JSON을 넣으면 씬
  전체(모든 파트)를, 프리셋을 넣으면 한 파트를 보드가 복원한다. 사용자에게 주는 기본 산출물은
  임베드본 + 파트별 프리셋이지만, 씬 전체를 보드에서 다루고 싶다면 씬 JSON 경로도 유효하다.
- 파일명: 임베드본 `xconda_[sceneId].html`(예 `xconda_s8.html`), 프리셋
  `preset_[sceneId]_[part].json`(예 `preset_s8_a.json`). 엔진 껍데기 `xconda_engine.html`은
  스킬 assets에 있고 사용자에게 매번 주지 않는다.
- 대화창에는 감독 브리핑·검수·조정 다이얼만 쓴다(§15).

## 13-A. 씬 데이터 스키마 (scene-v1) — 공유 + 파트별

씬은 30초 제한으로 여러 파트(A/B/C/D1/D2/E…)로 쪼개지지만 **같은 사건·같은 공간**이라
공간·인물·레퍼런스를 공유한다. 그래서 씬 JSON은 공유 자산과 파트별 데이터로 나뉜다.

```json
{
  "schema":"xconda-scene-v1", "sceneId":"S8", "title":"...", "model":"Seedance 2.5",
  "room":  { },       // 공유 — 공간(방+가구). 40px=1m
  "refs":  { },       // 공유 — 레퍼런스 5그룹. @태그 씬 전체 고정
  "parts": [ ]        // 파트별 — 프롬프트·배우·카메라
}
```

전체 규격·필드 정의는 `scene-json-schema.md`와 정식 템플릿 `examples/template_scene_v1.json`에 있다. **씬 JSON을 만들기 전에 그 파일을
읽는다.**

### `room` (공유)

방+가구만. 40px=1m, `centerPx`가 방 중심. 배우·카메라는 여기 없다(파트별). 한 번 확정하면
파트가 바뀌어도 고정. **평면도는 이 좌표에서 브라우저가 SVG로 실시간 렌더**한다(파이썬 불필요).
공간 좌표는 확정 평면도에서 읽되, 기존 좌표 위에 새 가구를 얹지 않는다(겹쳐 무너진다 —
새로 깔고 방·배우·카메라만 유지). 가구 크기는 §13-C 카탈로그의 표준을 쓴다.

### `refs` — 레퍼런스 5그룹, 번호 고정 (핵심)

인물만이 아니라 **씨댄스에 넣는 모든 레퍼런스**(characters·backgrounds·props·audio·video)를
관리한다. `@Image`는 **인물 → 배경 → 소품 순 1~N 연속**(그룹 구분 없이), `@Audio`·`@Video`는
각각 1부터 따로.

★ **번호는 씬 전체에서 고정**된다. §7-A의 "상대순서 유지"를 v8에서 **절대 번호 고정**으로
강화한다 — 현우는 A에서도 C에서도 @Image1. 민희(@Image4)가 C에 안 나와도 깡철이는 여전히
@Image5다. 사람이 파트에서 빠져도 뒤 번호가 안 밀린다. 파트는 `usesRefs`로 "이 파트가 쓰는
태그"만 나열하고, 안 쓰는 번호는 목록에서 빠질 뿐 번호 자체는 유지된다.

인물 레퍼런스 설명에는 `background`/`lighting`/`배경`/`조명` 같은 분류 트리거 단어를 쓰지
않는다(§7-B) — 파서가 인물을 배경으로 오분류해 배우 0명이 된다.

### `parts[]` (파트별)

각 파트: `partId` · `title` · `duration` · `mode` · `appears`(등장 id) ·
`usesRefs`(쓰는 태그) · `blocking`(배우 위치·동선 px) · `cameras` · `prompt`(10블록).
프롬프트 10블록은 §5~12 규약을 그대로 따른다(한/영, 포지티브 락, 화각 도(°) 등). 대사는
`대사 — 화자: {대사}` 라벨 줄로 분리(§4).

## 13-B. 보드 state.items 포맷 — 씬 데이터를 보드로 내보낼 때

> **⭐ v8.9 우선 원칙 — 기본은 씬 원본을 넘기는 것이다.** Claude가 프리셋(state.items)을
> 직접 조립하면 mocap id·motionMarkers·좌표를 추측하게 되어 오류가 반복됐다. 그래서 **기본
> 산출물은 전체 씬 원본 `xconda-scene-v1` JSON**이고, 보드의 기존 SceneV1 어댑터가 이를
> `state.items`로 변환·검증한다. 아래 포맷 설명은 (a) 엔진의 [보드 JSON 다운로드]가 내부적으로
> 쓰는 형식이자 (b) 보드가 무엇을 만들어내는지 이해하기 위한 참고다. **Claude가 손으로
> state.items를 짜서 내보내는 경로가 아니다.** 특히 `motionMarkers`·mocap clip id·`beats.sub`는
> Claude가 채우지 않는다 — 보드가 `parts[].actions`를 변환할 때 카탈로그와 매칭해 만든다.

블로킹 보드가 실제로 먹는 저장 포맷은 `state.items[]`(픽셀)다. 엔진의 [보드 JSON 다운로드]는
`room.items` + 선택 파트의 `blocking`+`cameras`를 합쳐 이 형식으로 변환한다.

- 좌표계: **40px = 1m**. 회전 필드는 `hdg`가 아니라 **`angle`**.
- item 종류: `room`(방) · `prop`(가구, `kind`로 catalogKey 매칭) · `actor`(배우, `path`·`pose`) ·
  `camera`(`subjectId`·`cutRef`).
- `layer`: 생성물은 전부 `"space"`. **`perf` 레이어에 유령 가구가 중복 생성되는 버그**가 있어,
  공간 정리 시 `layer:"perf"` prop을 먼저 제거한다.
- 좌표는 씨댄스 프롬프트 본문에 절대 섞지 않는다(씨댄스가 숫자를 연출로 오인).

`kind` catalogKey 매칭: `책상|desk`·`의자|chair`·`소파|sofa`·`책장|bookcase`·`수납장|옷장|cabinet`·
`테이블|table`·`문`·`창문`·`전면유리창`.

### 프리셋은 `items`만이 아니라 파생 필드까지 채운다

보드가 씬 JSON을 임포트하면 자동 생성하는 파생 데이터를, **프리셋으로 줄 때는 씬 데이터에서
생성해 함께 넣는다.** items만 넣으면 배우 동작·대사 타이밍·컷 구간·연기 지시가 빠져 보드가
불완전하게 복원된다. `state`에 넣을 필드:

| 필드 | 무엇 | 씬 데이터의 출처 |
|---|---|---|
| `items[]` | 방·가구·배우·카메라 | room.items + 파트 blocking + cameras |
| `beats[]` | 컷 = 비트 (start/end/label/raw) | 파트 prompt.cuts (tc로 시간 파싱) |
| `dialogue[]` | 대사 (who/line/t0/t1) | 컷의 `대사 — 화자: {…}` 라벨 |
| `actionTimeline[]` | 컷별 동작 (text/range/duration) | 컷 산문(대사·SFX 제거) |
| `cameraCoverage[]` | 컷 커버리지 (subjectId/range/cutRef) | 파트 cameras + 컷 시간 |
| `cutPlan{}` | 컷 순서 (in/out/duration) | 파트 cameras + 컷 시간 |
| `performanceMap{}` | 인물별 연기 지시 | 06번 블록 `· 이름 — 서술` |
| `importedPrompt` | 영문 프롬프트 전문 | prompt.blocks 영문 조립 |
| `space{}` | 방 프리셋 (kind/locked/source) | room.kind |

- **⭐ R-21 — id를 새로 발급하면 참조도 함께 변환한다.** 배우에 보드 숫자 id를 발급할 때
  `actorIdMap[씬id]=보드id` 테이블을 만들고, 카메라 `subjectId`·coverage·`dialogue` 화자를
  **그 보드 숫자 id로 바꾼다.** 씬 문자열 id(`"daehan"`)를 그대로 복사하면 items에 없는 값을
  가리켜 참조가 끊긴다(실제로 났던 버그). 문도 `sourceId`(원본 id)를 남겨야 propTimeline
  매핑이 검증된다. 배우에도 `sourceId`/`actorId`를 남긴다.
- **낼 때마다 `verify_board.py`로 검사한다** — subjectId·propTimeline.targetId·sceneBundle·
  dialogue 참조 무결성. 종료코드 1이면 위반이므로 고쳐서 다시 낸다.
- `videoIR`은 보드 내부 중간표현이라 **보드에 위임**한다(프리셋에 넣지 않는다).
- 컷 시간은 `tc`("0-4초"·"0-11초")를 파싱해 range로. duration과 합이 맞는지 검산.

### `propTimeline` — 문 열기/닫기 시간표 (누락 시 문 애니메이션 안 됨)

파트의 `propActions`를 보드 id로 변환해 `state.propTimeline`에 넣는다.

```json
{ "targetId": 21, "actionType": "open_door", "start": 0, "end": 4 }
```

- `targetId`는 **보드 items의 문 객체 id**(원본 씬 id가 아니다). 그래서 room prop에
  `sourceId`(원본 id)를 보존해 매핑한다 — 원본 "119" → 보드 21.
- `actionType`: `open_door` · `close_door`. `start`/`end`는 **초 단위**(0~1 정규화 아님),
  `0 ≤ start < end ≤ cutLen`. `duration` 불필요.
- 누가 여는지는 여기 없다 — 배우 동작은 actionTimeline에. 열림 각도는 문 객체의 `openAngle`.
- 같은 문에 겹치는 이벤트를 만들지 않는다.

### `sceneBundle` — 전체 씬 원본 + 파트 전환 보관함 (누락 시 파트 전환 불가)

```json
{ "source": {…전체 xconda-scene-v1 객체…}, "activePart": "A", "snapshots": {} }
```

- `source`는 **전체 파트가 든 씬 원본 객체**(파일 경로·문자열 아님). 선택 파트만 넣으면 보드에서
  다른 파트로 전환할 수 없다. `activePart`는 `source.parts[].partId` 중 하나.
- `snapshots`는 **`{}`로 두고 보드가 채운다**(파트 편집 상태 보관). Claude는 비워서 낸다.

### 보드에서 편집한 프리셋을 저장할 때

Claude 생성 기준은 위 필드 목록이지만, **보드에서 편집한 것을 다시 저장할 땐 `boardPayload()`
전체를 보존**한다(저장 상태 전체). videoIR도 저장 상태에 있으면 보존되고, GLB 메시·믹서 등
런타임 객체는 보드가 재구성한다. 즉 사용자가 보드에서 만진 프리셋을 받으면 필드를 임의로
쳐내지 않는다.

프리셋 파일명: `preset_[sceneId]_[part].json`. 프롬프트가 완성된 파트만 뽑는다.

가능하면 보드의 `SceneV1.prepare(sceneData, part).payload` 변환 로직과 같은 결과가 나오도록
맞춘다 — 씬 JSON 직접 임포트 경로와 프리셋 경로의 id·필드가 어긋나지 않아야 한다.

## 13-C. 오브젝트 카탈로그 — 인간 키를 기준점으로

가구 px 크기를 감으로 정하면 씬마다 들쭉날쭉해진다. **표준 가구 치수(미터)를
`xconda_object_catalog.json`에 저장**해두고, 배치 시 불러와 40px=1m로 환산한다. 위치(x,y)는
평면도에서 읽되 크기(w,h)는 카탈로그 표준을 쓴다.

- 기준점: **사람 키 1.70m = 68px**. 가구 높이 비율로 검산(책상 0.75m≈배꼽 44%, 캐비닛
  1.90m≈사람보다 큼 112%, 소파 등받이 0.78m≈앉은 어깨).
- 각 오브젝트: `{kind, catalogKey, model, width, depth, height(m), note}`.
- 평면도 검증 시 사람 키 마커(68px)를 함께 그려 비율을 눈으로 확인한다.
- `place_helper.py`로 카탈로그를 불러와 `place(key,name,x,y,rotate)`로 아이템을 찍으면 크기
  계산이 자동화된다.

## 13-D. 엔진 제작 3단 검증 (필수)

엔진은 한 번 만들지만, HTML 섹션을 추가/제거할 때 태그가 깨지면 **렌더가 통째로 실패한다
(빈 화면 + 깨진 파일 아이콘).** 함수 정의가 빠지고 호출만 남아도 마찬가지다. 만들거나 고친
뒤 반드시 아래 셋을 통과해야 띄운다.

1. **`<div>` 열림 == 닫힘** (섹션 제거 시 닫는 태그까지 지워졌는지)
2. **Node `new Function(script)` 파싱** (문법)
3. **DOM 스텁으로 초기화 완주 + 씬 JSON 로드 실행** (함수 정의 누락·런타임 에러) — 평면도가
   실제로 렌더되는지까지 확인

JS 파싱만 통과하고 태그가 깨지면 브라우저에서 빈 화면이 된다. 세 번째(초기화 완주)가
함수 누락을 잡는 유일한 방법이다.

## 13-E. 임베드본 생성 — 씬 JSON을 만들면 자동으로 엔진에 넣는다

씬 JSON을 만들 때마다 **엔진에 그 씬을 심은 임베드본**(`xconda_[sceneId].html`)을 함께
만든다. 사용자가 드롭할 필요 없이 파일만 열면 바로 뜨는 완성본이다.

### 만드는 법

엔진 HTML의 `<script>` 끝(`toast` 함수 뒤, `</script>` 앞)에 아래를 삽입한다.

```js
/* ── 임베드 씬 자동 로드 ── */
const EMBEDDED_SCENE = { …씬 JSON 전체… };
(function autoload(){
  if(EMBEDDED_SCENE && EMBEDDED_SCENE.schema==='xconda-scene-v1'){
    try{ loadScene(EMBEDDED_SCENE); }catch(e){ console.error('임베드 로드 실패',e); }
  }
})();
```

- `EMBEDDED_SCENE`에 씬 JSON을 `json.dumps(scene, ensure_ascii=False)`로 그대로 심는다.
- `autoload`는 스키마가 맞으면 `loadScene`을 즉시 호출해 파트 탭·평면도·프롬프트를 채운다.
- 드롭 기능은 그대로 둔다 — 다른 씬 JSON을 드롭하면 임베드본을 덮어쓸 수 있다.

### 검증

임베드본도 §13-D 3단 검증을 거친다. 특히 **초기화 완주 실행 시 `autoload`까지 돌아
평면도가 자동 렌더되는지** 확인한다(DOM 스텁 + `new Function(script)()` 후 planWrap에
`<svg>`가 있는지).

### 재생성

씬 데이터를 고치면 씬 JSON을 고치고 임베드본을 다시 만든다. 임베드본은 씬 JSON의 파생물이라
**항상 씬 JSON이 원본**이다 — 임베드본만 고치지 않는다(다음 재생성 때 덮어써진다).

## 13-F. 자세(pose) 표준어와 파서 (v9.0 신설)

**한 줄로**: 보드는 자세를 한국어로만 알아듣는다. 씬 JSON은 영문(`sit`)을 써도 되지만,
보드로 나갈 때 반드시 한국어로 바꿔서 보낸다.

### 표준어 4종

| 표준어 | 받아주는 값(정규화 대상) |
|---|---|
| `서다` | stand · stands · standing · stood · idle · 기립 · 서 |
| `앉다` | sit · sits · sitting · seated · sat · perch · perched · 착석 · 앉아 |
| `눕다` | lie · lying · prone · 누움 |
| `무릎꿇다` | kneel · kneeling · 무릎꿇다 |

`pose` 값이 없거나 모르는 값이면 기본값은 `서다`다.

**크리처** — 어깨·손등·무릎 위에 올라앉은 동물은 `앉다`다. 바닥을 기어가는 중이어도 컷의 시작
상태가 올라앉은 것이면 `앉다`로 둔다. 보드의 자세는 컷 전체의 평균이 아니라 시작 상태를 가리킨다.

### 엔진이 하는 일 (`assets/xconda_engine.html`에 내장)

```js
pose: normalizePose(bl.pose, parsePoseFor(c.name || cid, poseText(p), '서다'))
```

읽는 순서는 **① 씬 JSON의 pose → ② 프롬프트 문장에서 추출 → ③ 서다** 다.
독립 파일 `assets/pose_parser.js`는 같은 코드이며, 보드 `app.js`를 직접 고칠 수 있는
환경에서 임포트 경로에 붙여 쓰는 용도다. 보드 코드를 못 고치는 환경에서는 **필요 없다** —
프리셋에 값이 이미 들어가기 때문이다.

### 문장 추출 규칙 (파서가 판정하는 방식)

- 사역은 주체의 자세가 아니므로 제외한다 — "박수가 깡철이를 의자에 **앉힌다**" → 박수는 판정 없음.
- 미수행도 제외한다 — "앉으려다 만다", "앉을 생각이다".
- 자세 전환이 둘이면 **마지막에 취한 자세**가 이긴다 — "앉아 있다가 일어선다" → `서다`.
- 인물이 여럿인 문단은 이름이 들어간 절만 골라 판정한다(`parsePoseFor`).
- 문장에 자세어가 아예 없으면(예: "고개를 숙인 채 서류를 읽는다") 추출은 실패한다 —
  이때는 씬 JSON의 `pose` 값이 유일한 근거이므로, **앉아 있는 인물은 씬 JSON에 반드시
  `pose`를 적는다.**

### 프리셋을 함께 낼 때

사용자 보드가 **프리셋(state.items) + 프롬프트 텍스트**만 받는 환경이면, 파트별 프리셋
`preset_[sceneId]_[part].json`을 임베드본과 함께 낸다. 만드는 방법은 하나뿐이다 —
**엔진의 `boardForPart()`를 그대로 실행해서 뽑는다.** 손으로 items를 조립하지 않는다
(v8.9: mocap id·motionMarkers·좌표 추측 금지).

프리셋의 `beats`가 비어 있는 것은 누락이 아니다 — 컷 구간은 보드가 붙여넣은 프롬프트
텍스트에서 뽑는다. 그래서 **프리셋과 프롬프트는 짝**이고, 사용자에게 넣는 순서를
안내한다: ① 프리셋 → ② 그 파트의 영문 프롬프트.



## 13-G. 좌표 → 문장 동기화 (v9.3 신설)

**한 줄로**: 보드 좌표는 씨댄스에 전달되지 않는다. 같은 내용을 프롬프트 문장으로 다시 써야 한다.

### 파이프라인이 둘로 갈린다

| | 입력 | 결과 |
|---|---|---|
| 블로킹 보드 | 프리셋 JSON(좌표) | 평면도 · 동선 시각화 |
| 씨댄스 | **프롬프트 텍스트만** | 영상 |

좌표를 아무리 정밀하게 잡아도 프롬프트에 없으면 영상에 반영되지 않는다. 반대로 프롬프트에만
쓰고 좌표를 안 고치면 보드와 영상이 어긋난다. **두 곳 모두 고쳐야 한다.**

### 빈칸을 남기면 모델이 채운다 — 양쪽 다

같은 실수의 정반대 두 얼굴이다. 실제로 한 번에 둘 다 겪었다.

| 쓴 것 | 나온 것 |
|---|---|
| "마주 붙인 데스크 **네 자리**" | 빈자리에 엑스트라가 앉아 있음 |
| "사람이 없는 **빈** 사무실 바닥" | 가구가 사라진 맨 콘크리트 공간 |

수를 세어주면 채우고, 비우라고 하면 지운다. **무엇이 그 자리에 있는지**를 말해야 한다 —
"네 자리 중 방대한의 한 자리만 사람이 앉아 있고 나머지 세 자리는 의자가 비어 있다",
"어깨 뒤로 복사기와 정수기가, 그 너머에 철제 사물함과 코르크보드 지도가 초점이 풀린 채 놓인다".

### 첫 프레임 공간 줄

각 컷의 첫 줄(시간 표기 바로 다음)에 넣는다. 좌표에서 계산한다.

```
FIRST FRAME SPACE — Hyunwoo is at frame-center in the foreground;
Baksu is at frame-center in the background;
Kkangchul is on Baksu's shoulder.
```
담는 것은 **인물 / 프레임 좌·중·우 / 깊이(foreground · mid-ground · background)** 뿐이다.
샷 사이즈·배경 가구·크기 비교·미터는 쓰지 않는다. 짧을수록 잘 먹힌다.

**씨댄스에 붙이면 위치가 옆·다른 가구로 가는 말 — 쓰지 않는다.** 패널(좌표)과 영문이 다른 말로
같은 자리를 가리키면, 씨댄스는 영문을 따르고 사람을 패널과 다른 곳에 둔다.

| 쓰지 말 것 | 씨댄스가 하는 일 | 대신 |
|---|---|---|
| `right behind` (바로 뒤) | `right`를 화면 오른쪽으로 읽어 그쪽으로 옮긴다 | `directly behind` 또는 깊이만 (`in the foreground`) |
| `reading … the height` (작게 보임) | `reading`을 서류 읽는 동작으로 실행해 책상으로 보낸다 | `at … the height` — 그런데 이 줄에는 크기 비교 자체를 넣지 않는다 |
| `is left standing` (그 자리에 남음) | `left`를 화면 왼쪽으로 읽는다 | `stays where he is` / `stays out of this frame` |
| `screen-left and screen-right` | 같은 축의 앞뒤인데도 양옆으로 벌린다 | 패널에서 실제로 좌우로 갈라진 컷에만. 앞뒤면 `stacked in depth on the same center axis` |
| 첫 프레임 줄의 가구 이름 (`side desk`, `lockers`) | 그 가구를 그 인물의 자리로 읽는다 | 가구는 03번. 이 줄은 프레임 좌·중·우와 전경·중경·후경만 |

연기·조명·카메라 무브는 여기 쓰지 않는다(각각 06·03·04번 소유).
연기·조명·카메라 무브는 여기 쓰지 않는다(각각 06·03·04번 소유).

### 도구

```
python3 assets/blocking_tools.py check scene.json   # 출력 전 필수
python3 assets/blocking_tools.py sync  scene.json   # 공간 줄 삽입·갱신(한국어)
```

`sync` 는 한국어만 갱신한다. 영문은 편집기의 자동 갱신이나 Claude가 맞춘다 — 두 열의 태그와
수치가 같아야 검수를 통과한다.

### 블로킹을 새로 잡을 때의 순서

1. 가구 실측 범위를 먼저 출력한다(중심이 아니라 **x·y 범위**). 중심만 보면 사람이 책상 안에 선다.
2. 통로를 찾는다 — 가구 사이 폭 1.2m 이상인 빈 띠가 배우가 설 수 있는 곳이다.
3. 앵커를 정한다(입구 · 주 통로 · 문 앞 · 책상 옆). 파트가 바뀌어도 같은 앵커를 쓴다.
4. 경로는 앵커를 잇되 가구를 관통하지 않게 경유점을 넣는다.
5. 카메라는 문 쪽 축 위, 화각에 맞는 거리(84° 4.5m · 63° 4.0m · 47° 3.0m · 29° 2.5m · 18° 2.0m)에 둔다.
6. `check` 를 돌린다. 0건이 될 때까지 고친다.
7. `sync` 로 공간 줄을 뽑고, 영문을 맞춘다.



## 13-H. 다인 컷 카메라 — 첫 프레임 기준으로 잡는다 (v9.5 신설)

### 컷이 시작하는 순간의 위치로 계산한다

블로킹의 좌표는 그 파트의 **시작 위치**다. 걸어 들어오는 인물은 컷이 끝날 때 전혀 다른 곳에 있다.
실제 사고 — 8-7 투샷을 두 사람의 최종 위치로 잡았더니, 첫 프레임에서 박수는 아직 사물함 앞이라
현우와 4.6m 떨어져 있었고 47° 화각에 둘이 들어오지 않았다.

컷마다 **어느 시점의 위치로 프레임을 잡을지** 사람이 정한다. 자동 판단하지 않는다.

### 두 사람이 화각에 안 들어오면, 나란히가 아니라 깊이로 겹친다

간격이 화각을 넘으면 카메라를 **두 사람을 잇는 선의 연장선**에 놓는다. 앞사람이 크게, 뒷사람이
작게 같은 축에 놓여 한 프레임에 들어온다. 8-7이 그렇게 풀렸다 — 현우 2.3m 앞, 박수 6.9m 뒤,
각도 퍼짐 0°. 원래 글콘티의 "현우 뒤쪽 캐비닛에서 박수가 불쑥"이 그대로 성립한다.

### OTS는 앞 어깨가 가까운 것이 정상이다

오버숄더 컷의 앞 어깨는 렌즈에서 0.5~1.0m다. 최소 거리 1.2m 규칙을 그대로 적용하면 OTS를
만들 수 없다. 카메라에 `"ots": true` 를 달면 검사에서 앞 어깨만 예외로 본다.

### 시선을 막는 것은 키 큰 가구뿐이다

책상·의자·소파·테이블·복사기는 넘어다 보인다. 시선 차단으로 판정할 것은 사물함·책장·벽·문뿐이다.
전부 벽처럼 취급하면 "대한이 책상 뒤에 있어 안 보인다"는 잘못된 판정이 나온다.
단 **걸어가는 경로**는 다르다 — 낮은 가구도 통과할 수 없으므로 경로 검사에서는 전부 장애물이다.

### 인서트 전용 인물

다른 공간에만 등장하는 인물(굿당 환영 등)은 본편 컷의 프레임 계산에서 제외한다. 보드 좌표상
방 안에 놓여 있어서 계산에 섞이면, 본편 컷 공간 문장에 그 인물이 나타난다.



## 14. 씬 JSON에 데이터 채우는 법 (room / refs / parts)

`examples/template_scene_v1.json`(v9.10)의 구조대로 세 덩어리를 채운다. **엔진 코드는 건드리지 않는다.**

- **room** — 확정 평면도에서 가구 좌표를 읽어 `items[]`. 크기는 §13-C 카탈로그. 40px=1m.
  기존 위에 얹지 말고 새로 깐다. 방·배우·카메라만 유지.
- **refs** — 5그룹, @태그 씬 전체 고정(§13-A). 인물 설명에 background/lighting 단어 금지(§7-B).
- **parts[]** — 파트마다:
  - `appears`/`usesRefs` — 등장 id와 쓰는 태그. 안 쓰는 번호는 유지.
  - `blocking` — 배우 위치·방향·자세·동선(px). 문에서 시작/이동은 path로.
  - `cameras` — 컷별 화각(도)·샷사이즈·subject.
  - `prompt` — 10블록(§5~12). 08 타임라인은 `cuts:true`+headKo/headEn, 컷은 `prompt.cuts[]`.
    대사는 `대사 — 화자: {대사}` 라벨 줄(§4). 화각은 도(°) 앵커 9단계만. 미디엄 대화 컷 기본 47°.

**파트를 추가할 때** room·refs는 재사용하고 `parts[]`에 항목만 더한다. 등장인물이 바뀌어도
@Image 번호는 고정.

작성 주의:
- 씬 JSON은 유효한 단일 JSON. `json.loads`로 검증한다.
- 확신 없는 좌표·값은 지어내지 않는다 — 평면도에서 확인하거나 사용자에게 묻는다.
- 러닝타임은 대사 길이(§8-16)로 계산해 파트를 30초 이내로 나눈다.
