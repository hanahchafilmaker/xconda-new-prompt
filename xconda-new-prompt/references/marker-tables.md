### 18-2. 인물 마커
02번 레퍼런스/범례 블록 **안에서만** `· 이름 — 설명` 형식을 쓴다.
- 이름 뒤에는 반드시 공백 한 칸 + 대시(`—`/`-`/`–`)가 와야 한다.
- `이름(설명)` 형식도 인식된다.
- 다른 블록(예: 05번 소품 락)에서 같은 "· 무엇 — 설명" 형식을 써도 이름으로는 안 잡힌다 —
  이름 스캔 범위 자체가 레퍼런스 블록 안으로 한정돼 있기 때문. 그러니 이 규칙 때문에
  따로 조심할 건 없고, 그냥 02번에 인물을 저 형식으로 적어두면 된다.

### 18-3. 소품 · 차량
아래 단어를 그대로 쓰면 조사가 붙어도 인식된다 (예: "승합차에서" → 승합차).
- 가구: 침대·테이블·의자·소파·책상·책장·옷장·싱크대
- 가전: TV·모니터·냉장고·세탁기·에어컨·스탠드조명
- 건축: 벽·기둥·원형기둥·계단·문·현관문·유리문·창문·전면유리창
- 야외: 자동차·승합차·가로등·벤치·나무·소품·폐가

★ **밴과 일반 승용차를 구분해서 쓴다.** "승합차"라고 쓰면 밴(긴 차체·창 여러 개)으로,
"자동차"라고 쓰면 일반 승용차로 배치된다. 같은 장면에 밴 한 대만 있으면 "자동차"라고
안 써도 되고 — 굳이 둘 다 쓰면 중복 방지 로직이 자동으로 같은 차로 묶는다.

영문 열을 써야 하는 상황이면 `van/minivan/minibus`→승합차, `car`→자동차,
그 외 `door/window/table` 등도 매핑되어 있어 최소한의 인식은 된다.

### 18-4. 카메라
04번 옵틱스·카메라 블록과 08번 타임라인에 아래를 반드시 포함한다.
- **컷 라벨**: `CUT##-#` 형식 그대로 (예: `CUT11-3`) — 이 라벨 기준으로 컷 구간을 나눈다.
- **화각**: 반드시 `숫자°` 형태 (예: `63°`) — 9단계 앵커 값(180/107/84/63/47/29/18/12/8)이
  그대로 `lensMm`으로 역변환된다.
- **무빙 키워드**: 슬로 푸시인 / 풀아웃 / 트래킹 / 핸드헬드 / 휩 팬 / 팬 / 틸트 /
  오빗·아크 / 크레인 / 줌 중 정확히 하나. (한 컷에 두 개 이상 쓰지 않는 건 원래 XCONDA
  §5 규칙이기도 하다.)
- **샷사이즈**: 와이드 / 미디엄와이드 / 미디엄 / 클로즈업 / 타이트 / 버스트 중 하나.
- **카메라 앵글**: 하이앵글 / 로우앵글 / 아이레벨 / 버드아이 중 하나.
- **방향어**: 팬·틸트·트럭·오빗·크레인처럼 방향이 있는 무빙엔 "오른쪽/왼쪽" 또는
  "위로/아래로"를 반드시 같이 쓴다 — 안 쓰면 파서가 기본값(오른쪽/아래)으로 처리한다.
- **피사체 언급**: 그 컷에서 누구를 비추는지 인물 이름을 문장 안에 그대로 언급한다 —
  파서가 그 이름을 찾아 카메라의 피사체(팔로우 대상)로 자동 연결한다.

### 18-5. 인물 동선
08번 타임라인에서 아래 동사를 자연스럽게 쓰면 인물의 동선(진입→안쪽→퇴장)이 자동으로
추정된다. 대본에는 정확한 좌표가 없으므로 어차피 추정 배치인데, 이 동사들을 넣어두면
그 추정이 훨씬 정확해진다.
- 시작: 등장 / 내리다 / 하차
- 심화: 안쪽으로 / 다가간다 / 들어선다 / 걸어간다
- 종료: 화면 밖 / 프레임 아웃 / 퇴장
- 뒤따름: 뒤따라 (앞사람과 같은 방향으로 배치, y좌표만 살짝 어긋남)

### 18-6. 참고
이 섹션은 프롬프트 "품질"을 위한 새 규칙이 아니다 — 잘 쓰고 있는 XCONDA 프롬프트를
블로킹 보드가 텍스트에서 정확히 읽어낼 수 있도록, 이미 쓰는 표현을 저 목록의 정확한
단어로 맞추는 것뿐이다. 목록에 없는 표현을 썼다고 프롬프트가 잘못된 것은 아니며,
그 경우 블로킹 보드에서 해당 항목만 수동으로 추가/보정하면 된다.
