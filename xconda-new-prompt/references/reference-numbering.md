# 레퍼런스 @Image 번호 배정·고정·분류 트리거 단어 (구 §7-A·§7-B)

> 이 파일은 SKILL.md에서 분리된 상세 규칙입니다. SKILL.md의 라우팅 표가 이 파일을 가리킬 때 엽니다.
> 규칙 내용은 원본 그대로이며 위치만 옮겼습니다.

## 7-A. 레퍼런스 번호 배정 규칙 (v6.1 신설) — 순서·연속·씬 내 고정

레퍼런스 번호를 아무렇게나 매기면, 같은 씬을 여러 클립으로 나눠 만들 때 파트마다 같은 인물이
다른 번호를 갖게 됩니다. 그러면 사용자가 업로드할 때마다 순서를 새로 외워야 하고, 한 번만
어긋나도 얼굴이 통째로 바뀝니다. 아래 세 가지를 순서대로 적용합니다.

### ① 분류 순서 — 인물 → 배경 → 소품 → 오디오 → 비디오

```
@Image1..N   인물   (사람 · 크리처)
@Image…       배경   (로케이션 플레이트 · 통로 · 구역)
@Image…       소품   (게시판 · 로커 · 무구 등 독립 오브젝트)
@Audio1..N   오디오 (대사 트랙 · 환경음)
@Video1..N   비디오 (얼굴 각도 · 카메라 무브 · 화이트모델)
```

분류 안에서는 **씬에 처음 등장하는 순서**로 매깁니다. 분류를 건너뛰지 않습니다 — 인물이
끝나기 전에 배경이 끼어들면 안 됩니다.

### ② 번호를 건너뛰지 않는다

`@Image1, @Image2, @Image4`처럼 중간이 비면 안 됩니다 — 단, 이는 **씬 전체 자산 목록**에서의
이야기입니다(아래 ③). Seedance 업로드 시에는 그 파트가 쓰는 번호만 올리되, **번호 자체는
씬에서 고정**됩니다.

### ③ 번호는 씬 전체에서 고정한다 (v8 — 절대 고정) ⭐

**v8부터 번호는 파트마다 재배정하지 않고 씬 전체에서 고정한다.** (v6.1의 "파트마다 상대순서로
다시 매긴다"는 폐기 — 아래는 v8 규칙이다.)

- 씬 전체 자산 목록을 만들고, 분류별(인물→배경→소품)로 **@Image1~N을 한 번 배정해 고정**한다.
- 각 파트는 그중 등장하는 것만 `usesRefs`로 나열한다. **안 쓰는 번호는 비워둘 뿐 번호는 그대로.**
- 즉 현우는 어느 파트든 @Image1, 깡철이는 어느 파트든 @Image5. 사람이 빠져도 뒤 번호가
  안 밀린다.

예 — 씬 기준 순서가 `현우 · 대한 · 박수 · 민희 · 깡철이`(@Image1~5)일 때

| 파트 | 등장 인물 | usesRefs (번호 고정) |
|---|---|---|
| A | 현우, 대한 | @Image1 · @Image2 |
| C | 현우, 대한, 박수, 깡철이 | @Image1 · @Image2 · @Image3 · @Image5 (민희 @Image4는 미사용, 번호 유지) |
| E | 현우, 대한, 박수, 민희, 깡철이 | @Image1 · @Image2 · @Image3 · @Image4 · @Image5 |

깡철이는 **모든 파트에서 @Image5**다. 사용자는 번호를 다시 외울 필요가 없다.

### ④ 02번 블록에 씬 기준 순서를 명시한다

각 파트의 02번 첫 줄에 그 파트의 업로드 순서를 쓰고, 그 아래에 **씬 전체 순서**를 한 줄로
덧붙입니다. 파트를 오가며 작업할 때 사용자가 대조할 근거가 됩니다.

> 업로드 순서가 곧 번호입니다 — 이미지 N장을 아래 순서대로 올리고, 영상 한 개와
> 오디오 한 개를 따로 올립니다.
> 파트 기준 순서 — 인물(현우 · 대한 · 박수 · 민희 · 깡철이) → 배경(책상 구역 · 응접 구역 ·
> 캐비넷 통로) → 소품(게시판 · 로커). 이 클립에는 그중 등장하는 것만 1번부터 이어 붙였습니다.

### ⑤ 씬 JSON에도 기록한다

`scene` 오브젝트에 `referenceOrder`를 넣어, 보드와 다음 세션이 같은 순서를 복원할 수
있게 합니다.

```json
"scene": {
  "sceneId": "S8",
  "referenceOrder": {
    "characters": ["hyunwoo", "daehan", "baksu", "minhee", "kkangchul"],
    "backgrounds": ["office_desk", "office_lounge", "cabinet_passage"],
    "props": ["corkboard_map", "locker_front"],
    "audio": ["dialogue"],
    "video": ["hyunwoo_head_angles"]
  }
}
```

### ⑥ 검수 — 16항목으로 늘린다

기존 15항목에 아래를 더합니다.

- **16. 레퍼런스 번호가 1부터 빈틈없이 이어지고, 분류 순서(인물→배경→소품)가 지켜졌는가**

번호가 비었거나 배경 뒤에 인물이 오면 경고합니다.

## 7-B. 인물 레퍼런스 설명에 분류 트리거 단어를 쓰지 않는다 (v6.3 신설)

블로킹 보드 파서는 02번 레퍼런스의 **설명 문장 전체를 스캔**해서 그 레퍼런스가 인물인지
배경인지 분류합니다. 그래서 인물 레퍼런스 설명에 `background`·`lighting`·`배경`·`조명`
같은 **분류 트리거 단어**가 들어가면, 파서가 그 단어를 보고 **인물을 배경 항목으로 잘못
분류**합니다.

실제 사고: `@Image1 — 현우 ... Do not reference background or lighting.` 이라고 쓰면
`background` 때문에 현우가 배경으로 빠집니다. 그 결과:
- 배우: 0명
- 카메라 피사체: 전부 `null`
- 런타임: 피사체 없는 커버리지가 제외되어 **빈 화면**

**해결 — 담당/비담당을 그 단어 없이 쓴다.**

| ❌ 파서를 오염시키는 표현 | ⭕ 안전한 표현 |
|---|---|
| 얼굴·의상만 담당. **배경·조명**은 참조하지 않는다. | 이 인물의 얼굴·옷에만 쓰고, 주변 세트나 빛은 가져오지 않는다. |
| face and wardrobe only. Do not reference **background or lighting**. | Use this reference only for the person's face and clothing; do not copy the set or the light around them. |

배경(로케이션) 레퍼런스 쪽에는 `background`/`배경`을 써도 됩니다 — 그건 실제로 배경이니까요.
문제는 **인물** 레퍼런스 설명에만 국한됩니다.

★ 근본 해결은 파서가 "설명 문장 단어"가 아니라 "대시 앞의 실제 참조 대상"(`· 이름 — 설명`의
이름)으로 분류하는 것이지만, 그건 보드 코드 수정 사항입니다. 이 조항은 그 사이 데이터
쪽에서 사고를 막는 우회입니다.
